# 4os — задачи и проекты

Репозиторий для разнообразных задач, проектов и связанных с ними материалов: документов, подборок, исходного кода и средств публикации. Литературные конкурсы — одно из направлений работы.

## Разделы

| Папка | Содержание |
| --- | --- |
| [literary-competitions/](literary-competitions/) | Списки литературных конкурсов на разных языках, правила их ведения, шаблоны и сайт для GitHub Pages |

## Опубликованный сайт

Главная страница со списком всех задач и подпроектов: **https://l3chat.github.io/4os/**.

Структура адресов соответствует папкам проектов в репозитории:

| Исходные файлы | Раздел сайта |
| --- | --- |
| `index.html` | [Все проекты](https://l3chat.github.io/4os/) |
| `literary-competitions/docs/` | [Литературные конкурсы](https://l3chat.github.io/4os/literary-competitions/) |

Папка `docs/` внутри проекта содержит исходники его страниц. Её содержимое публикуется в разделе с именем проекта, без дополнительного сегмента `docs`.

Новые задачи добавляются отдельными папками на верхнем уровне. В каждой папке хранится собственный README с описанием задачи, структурой файлов, порядком работы и, при необходимости, инструкциями по публикации. При добавлении проекта обновить таблицу в этом README и список на главной странице `index.html`.

## Общие принципы

- Материалы, шаблоны, скрипты и настройки конкретной задачи хранятся в её папке.
- Общая таблица разделов в этом README обновляется при добавлении новых проектов.
- История изменений сохраняется в Git. Правила и инструкции для ИИ-агентов действуют в рамках соответствующей папки.
- Исполняемые workflow GitHub Actions находятся в корневой `.github/workflows/`, как требует GitHub; пути в них указывают на файлы конкретного проекта.

## Литературные конкурсы

Описание проекта и порядок публикации: [literary-competitions/README.md](literary-competitions/README.md).

Общий workflow: [pages.yml](.github/workflows/pages.yml). Он собирает литературные конкурсы из `literary-competitions/docs/` в `_site/literary-competitions/`, добавляет корневые `index.html` и `404.html`, проверяет ссылки всего сайта и публикует единый результат `_site/`.

Для нового публикуемого проекта добавить в общий workflow сборку или копирование его страниц в `_site/<имя-папки>/`. Все подпроекты публикуются одним workflow; отдельные публикации в тот же Pages-сайт перезаписали бы результат друг друга. Внутренние ссылки должны учитывать общий базовый путь `/4os/` и имя проекта.

Фактический адрес и состояние публикации показывает [Settings → Pages](https://github.com/l3chat/4os/settings/pages). Для публикации используется источник **GitHub Actions**.
