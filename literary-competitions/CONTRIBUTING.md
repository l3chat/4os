# Добавление и обновление конкурсов

Эти правила относятся к проекту `literary-competitions/`. Все пути в тексте указаны относительно этой папки. Общий исполняемый workflow находится в `../.github/workflows/pages.yml`. Раздел сайта публикуется по адресу `/4os/literary-competitions/`.

## Источники

- Использовать официальный сайт организатора и правила конкретного сезона. Сторонние подборки служат отправной точкой поиска.
- Записывать дату проверки в ISO 8601: `2026-10-31`.
- Если информации нет или страницы противоречат друг другу, явно указать неопределённость. Не переносить сроки прошлого сезона как подтверждённые сроки нового.
- Отделять требования организатора от редакционных рекомендаций, включая советы по темам.
- Не отмечать конкурс как открытый только по дате: проверять, что приём действительно объявлен.

## Структура карточки

Первичные данные находятся в `research/<язык>/catalogue.json`; правила — в [research/README.md](research/README.md). Поиск и оформление выполняются независимо. После изменения данных запустить `python3 scripts/render_catalogue.py` из папки проекта и сохранить также сгенерированные Markdown и JSON для скачивания. Скрипт обрабатывает все языки; `--language uk` выбирает один. Для изменения оформления достаточно изменить скрипт и перегенерировать файлы; повторный поиск не нужен. `--check` проверяет синхронность данных и представления в CI.

Каталог — список с закрытыми `<details>`: краткая строка показывает частоту, дедлайн, взнос и приз; раскрытая часть содержит полные условия и источники. Отдельно указывать, подаётся ли рукопись или уже изданная книга. Не смешивать одноимённые премии разных организаторов.

Ниже — формат для отдельных вручную составляемых списков:

Пользоваться [шаблоном](templates/contest-list.md). Для каждой записи нужны стабильный ID, название, официальная ссылка, сезон, язык произведений и дата проверки. Остальные поля заполняются фактами или пометкой «не уточнено» на языке страницы.

ID, например `en-example-award-2026`, обозначает конкретный сезон конкурса. Он не меняется при перестановке карточки. Для многоязычного конкурса допустим один общий ID в нескольких языковых разделах; сведения в этих карточках нужно синхронизировать. Если важна прежняя нумерация из исходного документа, сохранить её отдельным полем.

Срок указывать с датой, временем и часовым поясом, если они опубликованы. Взнос и призы записывать вместе с валютой; различать денежный приз и публикацию. Ограничения по возрасту, месту жительства, ранее опубликованным произведениям и использованию ИИ не предполагать: сверять с правилами.

Статусы: приём открыт; приём закрыт; будущий сезон не объявлен; требует проверки. Использовать эквиваленты на языке страницы. Закрытые конкурсы сохранять в годовом списке.

## Файлы и ссылки

- Кодировка UTF-8, окончания строк LF, имена файлов без пробелов.
- Годовые списки: `docs/contests/<язык>/<год>.md`.
- Каждая страница сайта начинается с YAML front matter: `layout`, `title`, `lang`.
- Не помещать черновики и персональные данные в `docs/`: содержимое этого каталога предназначено для публикации.
- Для внутренних ссылок на сайте использовать путь без `docs`, с фильтром `relative_url`:

```liquid
[Список за 2026 год]({{ '/contests/en/2026.html' | relative_url }})
```

Страница `2026.md` публикуется как `2026.html`, страница `index.md` — как `index.html`. Ссылки из README и других документов вне сайта остаются обычными относительными ссылками на файлы репозитория.

## Проверка и публикация

Pull request запускает сборку и проверку ссылок без публикации. Изменение `main` запускает сборку, проверку и публикацию через Pages, если Pages включён. При сбое открыть Actions и исправить причину; не обходить проверки для публикации.

В сообщении коммита кратко описывать результат, например: `Update English competition deadlines for 2026`. Крупные изменения содержания и изменения инфраструктуры желательно фиксировать отдельными коммитами.

Значимые изменения записывать в `../history/events.json` с фактическим временем и кратким результатом. Прошлые события должны ссылаться на существующие коммиты; для текущего набора изменений допустимо `commit: null`. После правки запустить `python3 scripts/render_history.py`, сохранить обновлённые `../CHANGELOG.md` и `docs/history.md`. Не редактировать производные журналы вручную. CI проверяет их через `--check`.
