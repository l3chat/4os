# Литературные конкурсы · Literary competitions

Создание, хранение, публикация и обновление списков литературных конкурсов на разных языках.

Этот проект находится в папке `literary-competitions/` общего репозитория [l3chat/4os](https://github.com/l3chat/4os). Другие задачи размещаются в отдельных папках; см. [корневой README](../README.md). Проверенные факты хранятся в JSON, представление создаётся в Markdown; сайт собирается Jekyll и публикуется через GitHub Pages.

## Состояние проекта

После дополнительного поиска каталог содержит 50 англоязычных записей из 9 стран организаторов и 20 украинских/украиноязычных записей, включая диаспорные и международные конкурсы. К исходным 22 и 17 добавлены 28 и 3 записи соответственно. Проверка — 31 октября 2026 года. В число записей входят конкурсы и отдельные конкурсные категории, а также закрытые сезоны с ожиданием нового срока. Охват остаётся неполным.

[Англоязычный каталог](https://l3chat.github.io/4os/literary-competitions/contests/en/catalogue.html) · [Украинский каталог](https://l3chat.github.io/4os/literary-competitions/contests/uk/catalogue.html) · [Порядок исследования](research/README.md) · [История событий](../CHANGELOG.md).

Оба каталога представлены компактными нумерованными списками названий. Нажатие на название увеличивает отступы вокруг записи и раскрывает краткие сведения; «Подробнее» открывает полные условия и источники. Поиск сохраняется отдельно от представления и не повторяется для изменения оформления.

Адрес раздела: **https://l3chat.github.io/4os/literary-competitions/**. В корне сайта находится [список всех проектов](https://l3chat.github.io/4os/). Состояние последней публикации показывает Actions.

## Первое включение GitHub Pages

1. Открыть [Settings → Pages](https://github.com/l3chat/4os/settings/pages).
2. В **Build and deployment → Source** выбрать **GitHub Actions**.
3. Открыть [Actions](https://github.com/l3chat/4os/actions), выбрать **Build and publish project sites** и нажать **Run workflow** для ветки `main`.
4. Проверить успешное завершение `build` и `deploy`. Адрес сайта появится в результате `deploy` и в Settings → Pages.

После настройки каждый push в `main` запускает сборку и публикацию. Для pull request выполняется только сборка и проверка; сайт обновляется после слияния в `main`.

**Приватный репозиторий.** По документации GitHub, Pages для приватных репозиториев требует подходящего платного плана, например GitHub Pro. Если Pages недоступен, сначала нужно выбрать подходящий план или отдельно принять решение о смене видимости. Инфраструктура не меняет видимость репозитория. Опубликованные страницы Pages обычно общедоступны даже при приватном исходном репозитории.

Документация GitHub: [публикация сайта](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site), [собственный workflow](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages).

Пути к исходным файлам указаны относительно папки `literary-competitions/`, кроме явно указанных корневых файлов. Раздел публикуется с базовым путём `/4os/literary-competitions`; пути языковых списков продолжаются после него, например `/4os/literary-competitions/contests/en/`.

## Как добавить список

Для исследовательского каталога создать `research/<язык>/catalogue.json` по [правилам исследования](research/README.md), выполнить `python3 scripts/render_catalogue.py` и добавить ссылку на каталог в языковую страницу. Скрипт автоматически обнаруживает новые языковые данные.

Для отдельного вручную составляемого годового списка:

1. Скопировать [шаблон](templates/contest-list.md), например в `docs/contests/en/2026.md`.
2. Заполнить заголовок, язык, год и карточки. Удалить подсказки и незаполненные примеры.
3. Добавить ссылку на годовой список в `docs/contests/en/index.md`, используя `relative_url`, как описано в CONTRIBUTING.
4. Зафиксировать изменения в GitHub. Проверить результат workflow в Actions.

Для дополнительного языка создать каталог с кодом BCP 47, страницу `index.md`, добавить её в `languages` файла `docs/_config.yml` и в таблицу README.

## Проверка

GitHub Actions собирает раздел Jekyll в корневой `_site/literary-competitions/`, добавляет главную страницу общего сайта и проверяет локальные ссылки, изображения и якоря во всём итоговом HTML. При ошибке публикация не выполняется. Внешние ссылки автоматически не проверяются: доступность страницы не подтверждает актуальность условий конкурса.

Если общий сайт уже собран локально в `_site`, ту же проверку можно запустить с Python 3 из корня репозитория:

```bash
python3 literary-competitions/scripts/check_links.py _site --base-path /4os
```

Для нового домена или переименования репозитория изменить `url`, `baseurl` и `repository_baseurl` в `docs/_config.yml`, корневую страницу `404.html` и `--base-path` в workflow. При переименовании папки проекта также обновить каталог результата сборки и ссылку на главной странице сайта. Секреты и дополнительные токены для обычной публикации не нужны: workflow использует штатный `GITHUB_TOKEN`.

## Редакционные правила

Сроки, взносы, ограничения, языки произведений и правила применения ИИ проверяются по официальным источникам. Дата проверки записывается в карточке. Неизвестные сведения отмечаются явно. Рекомендации по выбору темы отделяются от требований организатора. Подробности — в [CONTRIBUTING.md](CONTRIBUTING.md).
